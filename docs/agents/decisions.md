# Decision log

| ID | Date | Decision | Rationale | Owner |
|---|---|---|---|---|
| D-001 | 2026-10-31 | Monorepo lives at the repository root (`FixMySpine`), not in a nested `align/` folder. | The repo exists only for this app; nesting adds a path level for no benefit. | Lead |
| D-002 | 2026-10-31 | Swift code is split into a local Swift package `ios/AlignKit` (AlignCore, PostureDetection, Sensors) plus an app target. | Lets the core logic be tested with `swift test` without the app, and enforces module boundaries. Replaces the flat `ios/Core`, `ios/Sensors`, `ios/PostureDetection` folders in the brief. | Lead |
| D-003 | 2026-10-31 | The Xcode project is generated with XcodeGen from `ios/project.yml` and not committed. | Hand-editing `.pbxproj` without Xcode is error-prone; development happens on Windows and CI runs on GitHub macOS runners. | Lead |
| D-004 | 2026-10-31 | iOS 17 minimum; SwiftUI + Observation + SwiftData + Swift Charts; XCTest for tests. | Modern native stack with no third-party dependencies; XCTest runs on all Xcode versions in CI. | Lead |
| D-005 | 2026-10-31 | Tilt is estimated from the head-frame gravity direction relative to a calibrated baseline gravity vector, not from Euler angles or raw attitude comparison. | Excludes heading by construction, avoids gimbal lock and angle wrap, and keeps stored baselines valid across sessions despite the arbitrary heading reference. | Lead (Algorithm may challenge with evidence) |
| D-006 | 2026-10-31 | Detection is rules-based (smoothing, thresholds, hysteresis, duration, cooldown). No ML in Phase 1. | Brief requirement; ML only with evidence it beats the baseline. | Lead |
| D-007 | 2026-10-31 | Only sustained tilts are persisted as PostureEvents; raw motion is never persisted by default. | Data minimization. | Lead |
| D-008 | 2026-10-31 | Phase 2 (backend/analytics) is deferred; the Backend and Data agents are not started this session. | User chose to build Phase 0 + 1 first. | User |
| D-009 | 2026-10-31 | Commits are authored only by the repository owner; no AI attribution trailers. Agents commit on their own branches; the Lead merges to `main` and pushes. | User requirement. | User |
| D-010 | 2026-10-31 | The MVP monitors in the foreground only: no `UIBackgroundModes`. The session pauses when the app leaves the active state and resumes on return. | No background mode exists for headphone motion; the one report found says updates stop in the background; using audio background mode only to keep sensing risks App Review 2.5.4 rejection. Revisit after the S-05 hardware test. | Lead (from Sensor research) |
| D-011 | 2026-10-31 | `HeadAxisConvention.airPodsDefault` changed from forward (1,0,0) / lateral (0,1,0) to forward (−1,0,0) / lateral (0,1,0), assuming +X right ear, +Y nose, +Z up. | In a right-handed frame the chin-down axis × right-ear-down axis must point down; the old pair pointed up, so one sign was wrong. Community reports of pitch going negative when looking down fit the new pair. Still unverified until S-05. | Lead (proposed by Sensor) |
| D-012 | 2026-10-31 | Local data: the SwiftData store stays in normal (encrypted) device backups; history is kept until the user deletes it; "Delete all history" removes sessions and events only, with separate "Reset calibration" and "Reset settings" actions; default file protection (complete until first user authentication). App ships a `PrivacyInfo.xcprivacy` (UserDefaults CA92.1, SystemBootTime 35F9.1, no tracking, no collected data). | Simplest choices that keep the user in control; answers the QA privacy review's open questions. | Lead |
| D-013 | 2026-10-31 | App lifecycle: a session paused only because the app left the foreground resumes automatically on return; `.inactive` pauses the session but only `.background` stops the sensor provider. Xcode `SWIFT_VERSION` is `5.0` (Swift 5 language mode) with minimal strict-concurrency checking. The sensitivity preset is derived from the stored configuration rather than stored separately. | System alerts (including the motion permission prompt) make the app briefly inactive, so stopping the provider there would break the permission flow; Xcode only accepts language modes 4, 4.2, 5 or 6; deriving the preset avoids two settings disagreeing. | Lead (from Frontend) |
| D-014 | 2026-10-31 | The Phase 2 sync server will use Java + Spring Boot (with JPA and Flyway for PostgreSQL migrations) instead of Python/FastAPI. | User preference for a faster compiled language. The app stays fully offline-first; the server remains optional. | User |
| D-015 | 2026-10-31 | The algorithm's offline tools (reference pipeline, fixture generator, evaluation) move from Python to Java (JUnit 5, Maven), after the Algorithm agent's Python version lands. Fixture JSON format and Swift replay tests are unchanged. | User preference. The tools never ship in the app; the Python version is ported, then removed. | User |
